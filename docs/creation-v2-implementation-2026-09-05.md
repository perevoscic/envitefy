# Creation prompt implementation — September 5, 2026

The application now uses `creation-v2-2026-09-05` for the revised creation contracts. This implements the recommendations in the earlier analysis; that report's statement that production prompts were unchanged describes the original audit, not this implementation.

| Stage | Implemented behavior |
| --- | --- |
| Upload extraction | Strict JSON Schema, verbatim source transcript, per-field source quotes and observed/inferred/missing/conflicting status. Unsupported quoted evidence is rejected. Missing or conflicting birthday ages stay unknown. Impossible normalized dates are rejected. Conflicting OCR can receive one Astra review within the existing request budget. |
| Conversation corrections | Typed `set`/`clear` edits with an exact source quote and an allowlist. Existing host facts outrank uploaded facts. Original evidence remains available alongside later corrections. Model responses cannot set ownership, permission, publish status or readiness. |
| Readiness | Separate `canPreview`, `canSaveDraft`, and `canPublish`. Optional styling/RSVP questions do not block a preview. Publication checks required event facts, date confirmation, timezone, date ordering and unresolved source conflicts on the server. |
| Planning and copy | One structured response includes a creative plan and invitation copy. Inputs separate public facts, private direction, the output contract and approved wording. Optional notes may be empty. Code preserves supplied titles, schedules and locations. |
| Artwork | Explicit `live_card`, `digital_flyer`, `printable_flyer`, and `event_page` contracts. Live cards use title artwork and a reserved action area. Flyers use text-free artwork plus deterministic typesetting. Event pages request landscape, text-free heroes and retain existing page renderers. A plan cannot invent supported sections or override the product's text placement. |
| Export | Digital flyers: 1200×1800 PNG. Printable flyers: 1500×2100 PNG, 5×7 inches at 300 DPI, with safe margins. Names, wording, date/time, location, secondary stops and supplied RSVP/gift links are typeset by code. Excess text produces an explicit overflow error instead of truncation. Original export resolution survives upload persistence. |
| Checks | Astra inspects visible text, placement and supplied image references. Existing-image edits are compared with their source. One targeted repair is allowed; repeated failure cannot be presented as successful image generation. If the checker is unavailable, that status is returned explicitly. |
| Operations | Workload-specific output budgets and Astra effort, abortable requests, completion/refusal handling, and telemetry containing model/version/timing/token counts without source text or contact information. |

Key implementation files are `src/lib/creation/*`, `src/lib/ocr/extraction-contract.ts`, `src/lib/concierge/extraction-contract.ts`, `src/lib/concierge/action-contract.ts`, `src/lib/concierge/readiness.ts`, and `src/lib/studio/{product-contract,product-prompts,output-checks,flyer-export,generate}.ts`. Existing OCR, chat, Studio, persistence and download callers are wired to them. Legacy Studio prompt builders remain available as the comparison arm in the evaluation script.

The evaluation harness is `node scripts/evaluate-creation-v2.mjs`. Add `--live` for the two-model × two-prompt comparison, or `--live --smoke` for the four-call synthetic birthday check. Both prompt arms use the same workload budget policy so that a prompt change can be distinguished from a model change. Full production evaluation still needs representative uploads, languages, corrections and human visual review.

Validation artifacts are in `artifacts/creation-v2-*`. The initial targeted suite passed 409 checks, including 18 new contract/export checks. TypeScript reported zero diagnostics in the 34 checked application files; Biome passed across those files. Synthetic digital and printable exports were rendered and visually inspected. These samples verify typesetting, not image-model quality.

The broader scan identifies nine failing UI/authentication source guards, listed in `artifacts/creation-v2-broad-scan-summary.log`. The user explicitly deferred these on September 5. Several expect older helper/component shapes; the chat preview actions and Game Day RSVP behavior still warrant verification. They remain unresolved, and are not counted as passing checks.

The follow-through also removes conflicting legacy OCR instructions: extraction no longer asks for rewritten descriptions, inferred gender from decorative themes, or guessed missing years/times. The strict API schema is the sole response contract. The parser returns the description's verified source spans, preserving printed wording and languages; creative copy remains a separate stage. Existing calendar normalization handles partial dates from the retained transcript.

The final follow-through run passed all 394 library checks across creation, OCR, concierge and Studio, including regressions for literal multilingual descriptions and non-mutating parsing. Biome passed all five files edited in this follow-through. TypeScript found zero diagnostics in the 35 checked application files. Browser-discovery follow-up: the two diagnostics in `src/lib/discovery-browser.ts` are now fixed. Nearby text is read only after an `HTMLElement` check; the local page type declares the download event and its return type, removing the result assertion. Direct TypeScript validation reported zero diagnostics for this module and Biome passed. The 89-diagnostic artifact above is the earlier snapshot and predates these two fixes; the broader graph was not rerun for this narrow change. The nine deferred UI/authentication tests remain deferred.

A non-HTTP URL remains a string, so rejection must not narrow an existing string to `never`. The runtime format check is unchanged.
