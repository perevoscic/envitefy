# Person-aware scan titles and artwork

Snaps should describe the event in the person's terms. An ENT appointment notice should produce a short patient-first title rather than the clinic's administrative label. The extraction contract identifies the patient/honoree/participant separately from a provider or organizer. A labelled DOB supports age **at the event date**, never a birthday event or the appointment date itself. Ambiguous people and missing ages remain unknown.

New signed-in OCR saves carry `scanPersonalization` and the visually supported `scanSourceKind` (`paperwork`, `designed`, or `unknown`). Appointment slips, schedules, business/contact cards and paperwork default to generated artwork; designed invitations, posters and flyers keep the original hero. For signed-in, recognized paperwork, generation of a unique portrait hero and coordinated landscape background starts as soon as the validated event brief is available, before deep schedule extraction, location enrichment, source upload and the explicit save finish. Both save routes reuse this work without waiting for it; scans without an eligible early brief retain generation after saving. The same provider serves existing scanned event layouts. Owners can request a generated background for designed invitations; this makes only one image and keeps the original flyer visible throughout. Designed and unclassified sources always resolve to the original hero, including older saved events with missing/null scanSourceKind that previously selected generated artwork. Recognized paperwork always uses a generated hero, even when an older manual choice selected the original. The hero-switch buttons are removed; generation for an unclassified source creates only a background. The earlier invitation hero-switching behavior is superseded; source files and existing generated assets remain stored.

When a supported scanned layout shows the original in its hero, that hero opens the shared original-file popup with Share, Download and Close controls. The separate Original document tile is omitted. Paperwork retains the tile, as do sources without an available hero image (including PDF fallbacks). Medical sources remain owner-only. Display-time note filtering and extraction instructions keep Good to know for useful extras such as printed “Dinner and dancing to follow,” preparation, access and restrictions; generic reminders, empty placeholders and repeated logistics are omitted without deleting saved source facts.

The original remained visible before, during and after background generation and for legacy generated-hero selections. All four underlying scanned layouts opened the shared popup; exact download bytes, reopening without another fetch, Escape and focus restoration passed. Paperwork kept its tile, medical guests received no original controls, missing heroes kept the tile fallback, and generic notes disappeared. Unit checks confirmed one image generation/upload for designed sources and unchanged paired early generation for paperwork. Biome passed; direct TypeScript comparison found no new diagnostics (26 existing errors in three touched files), and two older source-shape guards already failed against HEAD. The VS Code diagnostics bridge was unavailable. Fixtures were removed; no saved event data or source files were changed by verification.

Appointment details retain the printed full patient name, Patient ID, individual clinician, Phone, Fax and clinic/organization. Medical appointment cards display **Clinician** for the individual and **Appointment provider** for the organization. Phone and Fax share one **Phone & Fax** tile, with separately labelled numbers and Phone first; single-number documents retain a single-purpose tile. Both remain distinct source facts. Labelled contact extraction handles parenthesized numbers and adjacent Phone/Fax fields, avoids treating a fax or patient ID as a phone, and recovers omitted contacts from saved OCR text without exposing the transcript. Phone facts are retained in the detail grid even if a separate contact shortcut exists. Stored Appointment Provider/Host facts remain intact for compatibility; extraction distinguishes the person from the organization and preserves printed credentials without assuming a doctor. Nonmedical role labels remain unchanged. DOB/birthday cards are hidden by the shared renderer, including on existing scans; source DOB remains available for age calculation. The generic “Bring your appointment details with you.” reminder is removed from copy and fact cards. Real printed preparation instructions remain intact.

Clinical scans use **Medical Appointments**, renamed from Doctor Appointments. ENT, dental, physical/speech/occupational therapy, lab tests and imaging cues are recognized; haircuts, car service and other nonmedical appointments remain **Appointments**. Legacy category names and internal doctor counters remain compatible. Existing scans resolve the same category and patient-first title in the sidebar, dashboard and event view, preserving saved URLs. Lightweight history queries retain the artwork profile, hero/background URLs, source/hero choice and patient-name facts needed for display; they omit DOB, patient IDs and source documents.

Artwork receives only a validated subject, motifs, supported age and an opaque random variation key. It receives no source document, patient name, DOB, address or patient identifier. Medical artwork uses reassuring objects; children's artwork suits their supported age, while adult/unknown-age artwork avoids childish assumptions. Existing saved scans can derive context from stored OCR facts and offer the owner **Generate event artwork**. Existing medical headings lacking the patient's name are corrected for display when stored facts clearly support it.

Generation uses the existing OpenAI image provider, then FFmpeg `libwebp` at quality 85/compression level 6. Dimensions, decoding and transparency are checked before uploading only the WebP. Generated originals remain in memory and are never uploaded. The `ffmpeg-static` binary is explicitly traced for the save, artwork and original-document routes; `SCAN_ARTWORK_FFMPEG_PATH` can override it.

Atomic event/owner/state claims prevent duplicate requests from generating two backgrounds. Completion merges only `scanArtwork`, checks its claim token and invalidates history/dashboard caches and the public event route. Failed jobs leave the event readable and offer an owner-only retry. Status polling is read-only and bounded; it never generates on a public page view. No draft is created by artwork generation.
